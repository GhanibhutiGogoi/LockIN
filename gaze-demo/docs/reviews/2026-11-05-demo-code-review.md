## 1. 高优先级：3–4 秒模型响应会让门控与恢复评估失效

位置：`backend/static/debug.js:119`、`:128`、`:132`、`:148`，`backend/lockin/signals.py:23`，`backend/lockin/recovery.py:19`。

调试页每 3 秒触发一次计时器，但上一请求未完成时直接跳过。如果模型每次用时 3.9 秒，实际截图发生在 0、6、12 秒。每个间隔都超过算法的 4 秒容忍值。此前实际 HTTP 接口已测到 3.92 秒，所以不是只在极端条件发生。

隔离复现：持续 120 秒娱乐输入，采样间隔为 6 秒，得到 0 次触发、最终 dwell=0；同样频率的持续学习输入，120 秒恢复窗口有效覆盖为 0、eligible=false。

影响：模型分类本身正确，真人 demo 却可能永远不触发，返回学习后也无法评估，更无法更新有效偏好。此前 1 秒间隔的模拟时序没有覆盖真实调度。

修复方向：统一采样、请求并发与允许的延迟预算；可分离高频 gaze 采集和低频屏幕语义更新，并严格标记各自新鲜度。不要仅把阈值放大到掩盖陈旧数据。补充真实耗时/限流/超时条件下的调度回归。

## 2. 高优先级：摄像头冻结或结束后仍能报告有效 gaze

位置：`backend/static/gaze.js:25`、`:26`、`:27`、`:47`。

视频循环只判断 `readyState`，没有判断摄像头轨道是否仍活跃，以及 `video.currentTime` 或实际帧计数是否推进。浏览器可能保留最后一帧。重复推理旧画面时又附上当前 `performance.now()`，使 `sample()` 把它当作新 gaze。

根代理隔离 Node 复现：使用真实 GazeCapture 类，替换浏览器设备和 worker 边界为测试替身。假视频 `currentTime` 始终为 1，摄像头轨道改为 ended；在时钟 6000ms 再次处理后，仍输出 valid=true、calibrated=true、on_screen=true。没有使用真实设备。

影响：摄像头缺失可能被当作注意力证据，导致错误触发、虚假的恢复覆盖以及不可靠的记忆推断。

修复方向：校验轨道 live/muted 状态和实际帧推进，处理 ended/mute，丢失新帧时使 gaze 失效；使用真实帧时间而不是重复绘制时间判断新鲜度。可复用主入口已有的帧有效性规则。补充轨道结束、视频冻结、后台节流测试。

## 3. 中高优先级：合计 7.8 秒的陈旧截图仍被接受

位置：`backend/lockin/app.py:99` 至 `:106`。

当前分别判断入站截图年龄和推理耗时各自是否超过 4 秒，推理结束后不再检查截图总年龄。3.9 秒旧帧加 3.9 秒推理都能单独过关。

审查代理用临时数据库、假 provider 和假时钟隔离复现：HTTP 200、accepted=true，娱乐分类 confidence=0.99，但写入观测时截图已老化至 7800ms。复现没有云端调用或用户数据。

影响：用户已经返回学习后，旧娱乐截图仍可能进入有效联合证据并触发。当前代码与 README 的 4 秒新鲜度约束不一致。

修复方向：推理结束、记录证据之前按当前会话时间重新计算截图总年龄；过期输出 unknown，并记录明确原因。补充网络排队+推理耗时组合测试。

## 4. 中高优先级：评估指标隐藏未知区间，并未评估最终门控

位置：`backend/lockin/evaluation.py:13` 至 `:25`。

未知预测直接被排除，召回率只统计有有效预测的片段。此外用的是单帧 evidence()，并非持续 8 秒后实际触发的门控输出。

根代理隔离复现：人工标注 120 秒全部分心，其中前 110 秒 gaze 无效，最后 10 秒检测到娱乐。输出 precision=1、recall=1、labelled_valid_ms=10000、fn_ms=0，没有总标注覆盖率。更短于 8 秒门槛的娱乐也可能得到帧级召回 1，即使没有实际触发。

影响：试用可能显示看似很高的识别率，掩盖漏检或大部分时间无法判断。用该结果选择阈值或比较模型会误导项目结论。

修复方向：报告全部人工标注时长、未知/缺失时长与覆盖率；把现有数值明确命名为“有效观测条件下的帧级指标”；另外计算基于门控输出的片段检测率、误报、漏报和触发延迟。补充大面积未知、无触发的短娱乐片段及跨界区间测试。

## Review 一般包含什么

1. 需求与实现是否一致，包括关键限制和可观察行为。
2. 正常逻辑、异常路径、时序、并发和边界条件是否正确。
3. 身份、数据隔离、凭据、隐私与输入校验。
4. 模块划分、职责、接口和以后调试维护的成本。
5. 测试是否有实际验证力，是否漏掉真实故障场景。

问题应附位置、触发条件、影响、证据和修复方向，并按用户影响分级。风格偏好不能替代实际故障判断。自动测试和 review 互补：测试验证已经写出的场景，review 追问哪些场景漏掉以及设计是否成立。
